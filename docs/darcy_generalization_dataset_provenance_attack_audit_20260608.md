# Darcy Flow Generalization Dataset Provenance Attack Audit - 2026-06-08

## Question

Audit whether the Darcy Flow generalization datasets used in the lossdrop50 and stockgeneralization experiments were generated by attacking the train/test tensors.

## Short Answer

Observed evidence says no: the Darcy Flow generalization datasets were generated as independent Darcy coefficient/solution datasets from GRF-style coefficient samplers and the JAX Darcy solver, then screened/selected by a short adversarial-training gradient/loss probe. They were not created by applying adversarial perturbations to existing train/test samples.

Important caveat: the selected 50-dataset suites are not unbiased random external generalization suites. They are selected from an independently generated pool using an observed loss-drop criterion, so they are deliberately screening-biased toward datasets where short self-training reduced eval loss.

## Generation Path Observed In Code

Observed from `tools/generate_darcy_generalization_candidates.py`:

- `generate_candidate()` calls `make_grf_batch_fn(...)` with candidate parameters such as `alpha`, `tau`, `low`, `high`, `soft_coefficients`, and `soft_beta`.
- It then calls `make_darcy_solve_fn(...)` and solves the Darcy equation for the sampled coefficient field.
- It saves payloads with `x`, `y`, `latent`, and `metadata` using `torch.save(...)`.

Observed from `tools/generate_darcy_lossdrop50_pool_20260607.py`:

- The lossdrop pool consists of 72 candidates from soft-coefficient families such as `soft_l4_h10_b8`, `soft_l4_h10_b10`, `soft_l4_h10_b12`, `soft_l4_h10_b14`, `soft_l4_h10p5_b12`, `soft_l3_h12_b6`, and `soft_l3_h12_b8`.
- Each pool candidate is described as an independent draw, for example `independent draw 9/18`.

No observed attack-generation fields such as `epsilon`, `steps`, `source=train`, `source=test`, or adversarial perturbation IDs are present in the Darcy dataset manifests. Those attack-related fields appear in training/probe scripts, not in the dataset generation path.

## Selection Path Observed In Code

Observed from `tools/select_darcy_lossdrop50_20260607.py`:

- It reads the pool manifest and a gradient-screen `candidate_screen_summary.csv`.
- It filters rows with `window == first50`, pool dataset names, and `eval_loss_delta < 0.0`.
- It sorts passing rows by loss delta/cosine metadata and takes the requested count.
- It hardlinks or copies the selected `.pt` files from the pool root into the selected root.

So selection does use adversarial-training probe results, but it does not create the dataset by adversarially attacking train/test inputs.

## Conclusion

Observed evidence:

- The Darcy Flow generalization datasets were independently generated from parameterized GRF/coefficient families and solved with the Darcy solver.
- The selected roots were created by hardlinking/copying from those generated pool datasets after screening.
- The train/test tensors were used by the gradient/loss screen and later training runs, but the selected generalization `.pt` files were not generated by attacking train/test samples.

Inference:

- This is materially different from the problematic Burgers attack-generated generalization root.
- However, the Darcy lossdrop50 and stockgeneralization roots remain screening-biased. They are valid for the specific loss-drop/self-training experiment design, but should not be described as an unbiased random external generalization benchmark.
