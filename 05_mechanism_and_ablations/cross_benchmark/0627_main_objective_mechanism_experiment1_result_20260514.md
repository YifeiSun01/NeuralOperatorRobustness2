# Experiment 1 Result: Main Objective Comparison Mechanism Diagnostics

Date: 2026-05-14

## Question

This record answers the Experiment 1 question from
`docs/loss3_original_theory_experiment_plan.md`:

> Are `loss1_original` and `loss2_original` reliable substitutes for
> `loss3_original`, or do they mainly find directions where the model output
> moves a lot while the oracle/solver moves in the same direction?

The diagnostic target is to separate:

- model movement: `||Delta f||`
- solver movement: `||Delta j||`
- model-solver mismatch: `||Delta f - Delta j||`
- true perturbed-input regression error: `||e(x + delta)||`
- alignment between model and solver response: `cos(Delta f, Delta j)`

In words, the experiment checks whether large model movement is mostly
"co-movement" with the solver.  If `Delta f` and `Delta j` are highly aligned,
then a large `||Delta f||` is not automatically a regression failure.  A truly
dangerous direction should make the model response fail to follow the solver
response, which appears as a larger `||Delta f - Delta j||` and a lower
`cos(Delta f, Delta j)`.

## Metric Definitions

Let:

```text
f0 = f(x)
j0 = j(x)
f_delta = f(x + delta)
j_delta = j(x + delta)
```

Then:

```text
Delta f = f_delta - f0
Delta j = j_delta - j0
Delta mismatch = Delta f - Delta j
e(x + delta) = f_delta - j_delta
```

Recorded metrics:

```text
||Delta f||              model output movement
||Delta j||              solver/oracle movement
||Delta f - Delta j||    model-solver response mismatch
||e(x + delta)||         true perturbed-input regression error
cos(Delta f, Delta j)    response alignment
D_f                      ||Delta f - Delta j|| / (||Delta f|| + eta)
D_sym                    ||Delta f - Delta j|| / (||Delta f|| + ||Delta j|| + eta)
```

## Main Finding

This experiment supports the claim:

> High model sensitivity is not the same as high regression error.

The central mechanism is:

> `Delta f` and `Delta j` often move in the same direction.  If the objective
> only encourages large model movement, such as `loss1_original`, or uses a
> fixed clean target, such as `loss2_original`, the attack can find directions
> where both the model and the solver change together.  These directions look
> sensitive, but they are not necessarily dangerous for regression because the
> model is still tracking the oracle response.

`loss1_original` mainly finds directions where the model output moves a lot.
But in these directions the oracle/solver also moves strongly and in nearly the
same direction.  Therefore the true model-vs-oracle mismatch is not maximized.

`loss3_original` directly targets the perturbed-input oracle-relative error.  It
does not necessarily maximize `||Delta f||`, but it does produce larger
`||Delta f - Delta j||`, lower `cos(Delta f, Delta j)`, and larger final
`||e(x + delta)||`.

Equivalently, optimizing only the size of `Delta f` tends to preserve a high
cosine similarity between `Delta f` and `Delta j`.  In the tables above,
`loss1_original` and `loss2_original` have cosine values around `0.91`, which
means the model response and solver response are highly aligned.  Optimizing
`loss3_original` lowers this alignment substantially, to about `0.56--0.62`
depending on the optimizer, and this lower alignment is exactly where the
larger mismatch comes from.

In the regression/operator-learning setting, this is the key distinction:

```text
loss1_original = large model movement
loss3_original = large model-oracle mismatch
```

The attack objective should be the latter.

## Follow-Up Experiment: FNO-vs-Solver Local Jacobian Similarity

The Experiment 1 result above shows a finite-radius phenomenon:

```text
loss1/loss2 directions:
  Delta f and Delta j are highly aligned
  cos(Delta f, Delta j) ~= 0.91

loss3 directions:
  Delta f and Delta j are less aligned
  cos(Delta f, Delta j) ~= 0.56--0.62
```

The natural next check is to ask whether this comes from the local linear
structure at the clean input:

> Are the FNO local Jacobian and the solver/oracle local Jacobian similar near
> the same input point?

If the answer is yes, then the Experiment 1 behavior has a clean mechanism:
many directions that make the FNO output move also make the solver output move
in a similar direction.  Therefore optimizing only model movement can produce a
false alert.  The dangerous directions should instead be directions where
`J_f - J_j` is large.

### Jacobians To Compute

At the clean input `x`, compute:

```text
J_f = d f(x) / d x
J_j = d j(x) / d x
J_e = J_f - J_j
```

where:

```text
f = FNO model
j = solver/oracle
e = f - j
```

For `nx=1024`, each Jacobian is `1024 x 1024`, so explicit Jacobian computation
is feasible.  The existing FNO/DeepONet Jacobian experiment already computed
`J_f` for FNO; this follow-up adds the solver Jacobian `J_j` and the residual
Jacobian `J_e`.

### Main Comparisons

#### 1. Singular Values

Compute SVD:

```text
J_f = U_f S_f V_f^T
J_j = U_j S_j V_j^T
J_e = U_e S_e V_e^T
```

Compare:

```text
S_f vs S_j vs S_e
spectral norm
Frobenius norm
effective rank
cumulative singular energy
```

Interpretation:

- If `S_f` and `S_j` are similar while `S_e` is smaller, the model locally
  tracks the solver well.
- If `S_e` has large singular values, there are strong local mismatch
  directions.

#### 2. Right Singular Vector Similarity

Right singular vectors are input perturbation directions.  Compare:

```text
abs(V_f_top^T V_j_top)
abs(V_f_top^T V_e_top)
abs(V_j_top^T V_e_top)
```

Use top `k = 16` or `32` vectors and plot heatmaps.

Interpretation:

- High overlap between `V_f` and `V_j` means FNO-sensitive input directions are
  also solver-sensitive input directions.
- Low overlap between `V_f` and `V_e` means the dangerous mismatch directions
  are not simply the most model-sensitive directions.

#### 3. Left Singular Vector Similarity

Left singular vectors are output response patterns.  Compare:

```text
abs(U_f_top^T U_j_top)
abs(U_f_top^T U_e_top)
abs(U_j_top^T U_e_top)
```

Interpretation:

- High overlap between `U_f` and `U_j` means model and solver produce similar
  output-shape changes in their dominant modes.

#### 4. Principal Angles Between Subspaces

Compare top-k input subspaces:

```text
span(V_f[:, :k]) vs span(V_j[:, :k])
span(V_f[:, :k]) vs span(V_e[:, :k])
span(V_j[:, :k]) vs span(V_e[:, :k])
```

for:

```text
k = 1, 2, 4, 8, 16, 32
```

Record principal angles or their cosine values.

Interpretation:

- Small angles between `J_f` and `J_j` subspaces support co-movement.
- Larger angles between `J_f` and `J_e` support the claim that mismatch
  directions differ from model-sensitivity directions.

#### 5. Fourier Basis Gain

For Fourier input directions `phi_k`, compute:

```text
||J_f phi_k||
||J_j phi_k||
||J_e phi_k||
```

for frequencies:

```text
k = 1..512
```

Plot gain-by-frequency curves.

Interpretation:

- This shows whether FNO and solver respond similarly across frequency bands.
- Peaks in `||J_e phi_k||` identify frequencies where model-solver mismatch is
  locally large.

#### 6. Direction Co-Movement Table

For representative directions:

```text
top right singular vectors of J_f
top right singular vectors of J_j
top right singular vectors of J_e
random directions
```

record:

```text
||J_f v||
||J_j v||
||J_f v - J_j v||
cos(J_f v, J_j v)
D_f = ||J_f v - J_j v|| / (||J_f v|| + eta)
D_sym = ||J_f v - J_j v|| / (||J_f v|| + ||J_j v|| + eta)
```

This table directly connects the local Jacobian experiment to Experiment 1.

Expected interpretation:

- Along `J_f` top directions, `||J_f v||` may be large, but
  `cos(J_f v, J_j v)` may also be high.  These directions explain why
  `loss1_original` can create large model movement without maximizing true
  mismatch.
- Along `J_e` top directions, `||J_f v - J_j v||` should be larger and
  `cos(J_f v, J_j v)` should be lower.  These are local high-mismatch
  directions, closer in spirit to what `loss3_original` searches for.

### Notes On Eigenvalues

Eigenvalues can be computed as an auxiliary diagnostic, but they should not be
the main evidence.  These Jacobians are generally non-symmetric, so eigenvectors
may be unstable and non-orthogonal.  For adversarial perturbations, SVD is the
more direct tool because it answers:

```text
which input direction v maximizes ||J v||?
```

If eigenvalues are included, record them as appendix-style diagnostics:

```text
spectral radius
complex eigenvalue scatter plot
top eigenvalue magnitudes
```

The main paper argument should use singular values, singular vectors, subspace
overlap, Fourier gains, and direction co-movement.

### Expected Contribution To The Loss3 Argument

This follow-up experiment would provide the local-linear explanation for the
finite-radius Experiment 1 result.

If `J_f` and `J_j` have similar dominant singular directions, then:

```text
high ||J_f v|| does not imply high ||(J_f - J_j)v||
```

because the solver may move in the same direction:

```text
J_f v ~= J_j v
```

This explains why `loss1_original` can maximize model movement but fail to
maximize true regression error.  The correct local mismatch object is:

```text
J_e = J_f - J_j
```

and the correct finite-radius attack object is:

```text
loss3_original = ||f(x + delta) - j(x + delta)||
```
